# 丸尾けいすけ公式サイト — 設計思想

## 1. このLPが伝えるもの

このサイトの目的は、情報量を並べることではなく、訪問者が短い時間で次の順序を体験することにある。

1. 「丸尾けいすけ」という人物を認識する
2. 「まっとうな政治に、マルを！」という姿勢を受け取る
3. 社会像と経歴から、その姿勢の背景を理解する
4. 5つの政策を、自分の生活との接点として読む
5. 応援・寄付・SNSという次の行動へ移る

したがって、デザインの中心は装飾ではなく、人物とメッセージの関係を切らさない情報体験である。

## 2. 画面の基本構造

### PC：右に人物、左に物語

PCでは、右側の写真と縦書きの「丸尾けいすけ」を固定する。左側だけが横方向にシフトし、9つの場面を切り替える。

- 写真は単なる背景ではなく、すべての主張の話者を示す「固定された主語」
- 左側は、プロフィールや政策を入れ替える「内容の舞台」
- 縦スクロール操作を横移動へ変換し、ページをめくるように話題を転換する
- 右側を動かさないことで、場面が変わっても人物とのつながりを維持する

左右を異なる背景ブロックに分けること自体が目的ではない。右側は人物の存在、左側は語られる内容という役割の差を、動きとレイアウトで示している。

### スマホ／タブレット：縦方向の物語

画面幅が限られる環境では、PCの左右分割を縮小しない。写真を画面の基層に固定し、その上をメッセージ、説明、プロフィール、政策が順に通過する縦方向のストーリーへ切り替える。

- 顔の上に、ぼかしのない本文を直接重ねない
- プロフィールは95vw程度の浮いたパネルとして提示する
- 長文はページ全体の通常スクロール量に対応して、固定パネル内部の位置を連動させる
- 政策への移行では色面をワイプさせ、写真の場面から政策の場面へ切り替わったことを示す

タブレットはPC版の縮小ではなく、スマホ版の物語構造を保ちながら、写真位置・本文幅・余白を広い画面向けに再配分する。

## 3. 固定される要素の意味

### 写真

写真はサイト全体の連続性を作る。PCでは常に固定し、スマホではコンテンツの背後に固定する。スクロールに合わせて写真そのものを移動させるのではなく、前景の情報が入れ替わることで場面を作る。

写真位置は画面比率に追従する相対単位で調整する。特定端末だけに合う絶対的な座標ではなく、顔・肩・腕が画面内でどう見えるかを基準にする。

### 「丸尾けいすけ」

名前は写真に結びつく人物ラベルであり、コンテンツ側へ置かない。縦書き・明朝・細めのウェイトによって、強い存在感と上品さを両立する。中央寄りに置くと本文と競合するため、写真側の外縁に寄せる。

### ヘッダー

ヘッダーは現在位置を示す索引である。PCでは主要セクションとプライバシーポリシーへの入口、スマホでは画面下部のナビゲーションとして機能する。LPの物語を途中から読める一方、ブランドから先頭へ戻れるようにする。

## 4. 文字の階層

最も重要なのは名前と「まっとうな政治に、マルを！」である。次に社会像、プロフィール、政策見出し、本文が続く。

| 層 | 役割 | 表現 |
|---|---|---|
| 人物名 | 誰の言葉か | 縦書き、明朝、細め、大きい |
| メインメッセージ | 立場を一瞬で伝える | 最大サイズ、明朝、「マル」を色と円で強調 |
| 社会像・政策名 | 場面ごとの主題 | 明朝、余白を広く、本文と明確な差 |
| 本文・具体策 | 理解を支える | ゴシック、十分な行間、両端揃え |
| 補助情報 | 所属・番号・SNSラベル | 小さめ、字間を広げる |

太さだけで強調すると政治的な力強さが前面に出すぎ、高級感と誠実さが失われる。サイズ、余白、色差でメリハリを作り、明朝のウェイトは必要以上に上げない。

## 5. 色の役割

- 濃紺 `#09254b`：信頼、制度、本文の可読性
- 青 `#007fbd`：中道カラー、現在位置、行動への入口
- 水色 `#ccebf4`：濃色面での補助情報と区切り
- 白：写真と文字を競合させない余白
- 黄色：メインコピーの「マル」だけを示す高透明度のアクセント

政策01〜05はカードごとに青〜青緑〜落ち着いた紫青へ変化する。色の違いは装飾ではなく、「今どの政策を読んでいるか」を直感的に区切るために使う。巨大で薄いアイコンも同じ目的で、カードの背景として政策の性格を補助する。

## 6. モーションの役割

モーションは「何かが動いた」ことを見せるためではなく、内容の位相が変わったことを伝えるために使う。

- PCの横シフト：章をめくる
- ビジョン見出しから説明文への交代：スローガンから理由へ焦点を移す
- プロフィールパネルの出現：写真中心の場面から経歴を読む場面へ移る
- 政策ワイプ：人物紹介から政策領域へ入る

スクロール量は連続値として扱い、単発のホイールイベントで複数場面を飛ばさない。PCの現在場面はスクロール位置から導出し、戻る方向でも同じ計算を使うことで、往復時の「カクつき」を避ける。

`prefers-reduced-motion` が指定された環境では、意味を失わない範囲でアニメーションを止める。

## 7. 9つの場面

| 番号 | 内容 | 主な役割 |
|---:|---|---|
| 01 | ヒーロー | 名前、所属、メインメッセージ |
| 02 | 社会像 | 政治を志す理由 |
| 03 | プロフィール | 経歴、記事、動画 |
| 04 | 政策01 | 未来世代 |
| 05 | 政策02 | 現役世代 |
| 06 | 政策03 | 先輩世代 |
| 07 | 政策04 | 気候危機と成長 |
| 08 | 政策05 | 食糧・地域・文化 |
| 09 | 応援 | 応援、寄付、SNS |

独立したフッタースライドは作らない。プライバシーポリシーはヘッダーメニューから別ページへ移動する。

## 8. プロフィールと政策の情報設計

### プロフィール

プロフィール本文は1列で読み、インタビュー記事と動画はその次のまとまりとして提示する。PCでは本文の下に2つのメディアを横並びにし、画面下部が不自然に空かないよう、枠全体を使って上下方向にも配分する。

### 政策

各政策は1枚のカードとして完結させる。番号、タイトル、要旨、具体策の順で読み、カード全体を画面の上下中央に収める。具体策は1列の箇条書きとし、カード内部に縦スクロールを残さない。

政策05の具体策は、現在の原稿では政策04と同文である。これはデザイン側で推測修正せず、正式原稿が確定した時点で `src/siteContent.js` を更新する。

## 9. レスポンシブの考え方

| 幅 | 構成 |
|---|---|
| 〜759px | スマホ向け縦ストーリー |
| 760〜1023px | 縦ストーリーを保ったタブレット調整 |
| 1024px〜 | 右固定＋左横シフトのPC構成 |

ブレークポイントは見た目の慣習ではなく、右側に人物を固定したまま、左側に文章を無理なく収められるかで決めている。1024px未満でPC構成を維持すると、本文幅が狭くなり、写真と名前と文字が競合するため、縦ストーリーへ切り替える。

確認時は代表端末だけでなく、320pxから1920pxまで段階的に幅を変え、次を観察する。

- 横方向のはみ出しがないか
- 固定写真の顔と本文が衝突しないか
- パネル内に意図しない縦スクロールがないか
- 1023pxと1024pxの切り替えで情報が欠けないか
- ナビゲーションと現在場面が一致しているか

## 10. 実装の読み方

実装は、変更理由を追いやすくするために次の責務へ分けている。

| ファイル | 責務 |
|---|---|
| `src/main.jsx` | 9場面の組み立てと移動命令 |
| `src/SiteSections.jsx` | ヘッダー、人物、各セクションのマークアップ |
| `src/siteContent.js` | 表示文、政策データ、外部URL |
| `src/siteConfig.js` | 場面番号、色、PC判定などの共有値 |
| `src/useSiteMotion.js` | PCの横移動とスマホのスクロール演出 |
| `site-refactored.css` | タイポグラフィ、配置、レスポンシブ、視覚表現 |

文章を更新する場合は `siteContent.js`、構造を変える場合は `SiteSections.jsx`、動きを変える場合は `useSiteMotion.js` を起点に読む。これにより、文言変更がスクロール制御へ波及したり、見た目の調整がデータへ混ざったりすることを防ぐ。
